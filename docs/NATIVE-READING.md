# 原生资料读取与长正文续读

本批修改现有个人上下文和分身建设流程。来源、候选、用户确认和历史版本仍各自保留；没有增加外部查询服务、向量数据库或自动确认个人偏好的流程。

## 行为

- 个人上下文选择只按关联 ID 读取来源的 ID 和标题，不再先加载全部来源正文。真正提供证据时仍使用既有受预算限制的来源摘录。关闭数字分身时，不读取认知集合。官网内存示例实现同一元数据接口。
- 新整理的正文生成 `processing` 检查点：版本、正文长度、当前段序号以及各段起止位置、状态、任务与摘要。索引和起止位置采用 JavaScript UTF-16 单元，起点包含、终点不包含。
- 每段最多 40000 单元，优先在附近换行处分段，并保留约 1000 单元重叠；不拆开代理对。同一份材料顺序调用现有 TaskRunner。相邻上下文只能减少常见的断句问题，不保证覆盖任意长度的跨段推理。
- 每段结果校验后作为一个持久检查点保存。后续段失败时，前段候选和摘要仍保留；重试不重放已保存的段。重启恢复已完成任务结果，但不自动发起新的模型调用。
- 候选引文只允许来自当前已提供的正文段或本轮附件。正文证据保存原文位置；重叠段中完全相同的候选合并，保留可核对的证据。近义表述不会自动合并。
- 来源变化时停止处理或确认，保留旧材料和进度，允许用户从更新后的来源重新整理。全部正文处理完后仍需逐条确认、修正或略过，才会写入长期个人记录。
- 界面显示完成段数、各段摘要和继续按钮；沿用已有组件和双语文案。没有用最后一段的摘要冒充全文摘要。

## 范围

本批没有放宽手动材料 40000 字符、普通来源正文 200000 字符、聊天导入或附件的现有限制。只有正文参与分段；附件仅首段发送，仍受既有格式、字节和文本截取限制。旧的已审阅截断结果不会自动重跑或覆盖。

当前改善的是任务取个人上下文时的来源读取。其他认知集合仍沿用现有排序方法，应用 bootstrap、资料列表、来源变化扫描和附件读取并未全面改为分页。没有批量导入整份历史档案、全局增量索引、跨资料记忆合并或新的语义检索。

分批整理会增加长正文的模型调用次数。用户点击探索后，继续使用所选模型和原有权限；分段本身不代表本地推理。此批验收没有调用真实提供方，也没有读取或发送私人聊天。

脚本建立临时数据库：256 份虚构来源，共 51200000 个字符，并在独立进程中交替测量各 5 次。旧方式模拟先加载完整来源映射，再执行同一选择逻辑；新方式按 ID 读取元数据。两者输出摘要完全一致。
